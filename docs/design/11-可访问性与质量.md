# 可访问性与质量

- 390×844 基线无横向溢出；中英文、浅深主题、辅助功能大字体、屏幕阅读器、reduced motion 均可用；触控目标 ≥ 44；所有交互有准确 Semantics（tab 角色与 selected 状态、列表行组合语义、可读的刷新／重试／密码切换名称），状态不只靠颜色表达，持久错误用语义化状态组件并带读屏标签。
- 键盘 Next／Done 顺序与焦点清晰；表单字段有 label、错误、键盘类型。
- 测试：单元、Widget、Golden、`integration_test`。原生 UI 回归与真实服务集成分开执行：`web_sync_ui_test`、`workspace_parity_test`、`admin_parity_test` 使用明确的 synthetic fixtures；`auth_flow_test`、`upload_flow_test` 与业务契约集成需要同版本独立服务和测试邮箱／账号。Synthetic 截图与 Golden 验证布局、交互和稳定视觉决策，不能替代真实鉴权、文件传输、Provider 或 AI 执行。
- 原生截图通过 `flutter drive --driver=tool/native_visual_driver.dart --target=integration_test/web_sync_suite_test.dart -d <simulator-id>` 生成；`FRAMEFETCH_QA_OUTPUT` 指向仓库外的输出目录。测试覆盖明暗主题、390 宽度与 2× 文字缩放，截图须人工复核。发布前分别记录静态检查、模拟器 UI、真实服务、真机与真实账号证据。
- Xcode 27／macOS 27.0.1 当前环境的通用 Simulator 构建受 `lipo -verify_arch arm64 x86_64` 工具链错误阻断，即使 framework 实际包含两种架构。指定 arm64 iPhone 的原生回归与正式 `lib/main.dart` 构建可通过；不修改 Flutter SDK，也不因此宣称 x86_64 或通用双架构通过。正式入口配置完成后，可执行 `xcrun xcodebuild -workspace ios/Runner.xcworkspace -scheme Runner -configuration Debug -sdk iphonesimulator -destination id=<simulator-id> ONLY_ACTIVE_ARCH=YES ARCHS=arm64 CODE_SIGNING_ALLOWED=NO build`；运行原生测试后须恢复正式入口配置。
- Flutter 官方已在 [3.44.8 热修复记录](https://github.com/flutter/flutter/blob/3.44.8/CHANGELOG.md) 中收录 [Xcode 27 lipo 修复](https://github.com/flutter/flutter/pull/189792)。本仓库目前仍固定 3.44.7，升级后的双架构结果须重新验证。
- 指定 arm64 模拟器的实际安装与启动使用 `flutter run --debug -d <simulator-id>`，由 Flutter/Xcode 完成 Simulator 制品的本地签名；`CODE_SIGNING_ALLOWED=NO` 的构建成功不代表该未签名制品可直接安装运行。真机与商店签名另行验收。
