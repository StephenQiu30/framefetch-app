# 链接解析与下载

## 链接解析与下载创建

- 首页与 Web 的 `content-intake-hero` 同步：无强制换行的标题、简介、链接／视频／剧本入口，内容最大宽度 1280px 左对齐；标题到入口间距手机 40px、大屏 48px，入口到表单 24px。标题用统一页面介绍组件的大标题样式；不再显示旧信任页脚与链接支持文案。
- 来源入口普通字号使用灰底圆角分组与白底选中项，不显示下划线；大字体保留竖排满宽入口，每项至少 44px。解析结果、统一历史与分析详情复用共享导航条，保留品牌、返回、主题和资源入口。
- 输入原始链接或整段分享文案，保留原始换行；服务端提取并校验恰好一个 HTTP(S) URL（客户端只拒绝空输入）。
- 采用服务端持久解析意图：`POST /api/download-intents`（UUID 幂等键）→ 按意图 ID 轮询。响应不明时先以幂等键只读 GET 收敛，不自动重发；404 后用户显式重试才复用同一键。首页不展示或请求近期解析列表，完整处理历史位于独立页面。账号变化立即清除，进程内只存 ID 与状态，不持久化原文、Cookie 或媒体直链。
- 状态：仅 `ready`、inspection 未过期且 `downloadable` 才可确认格式；结果过期显示显式“更新”（`POST /{id}/refresh` 保留原意图，开启新 generation 并重新确认，不自动下载）；`handed_off` 进入下载详情。公众号文章先来源发现，多候选由用户选择。
- 平台来源和执行上下文由服务端确定。`queued/resolving` 只观察原意图并允许取消，`cancelling` 持续轮询直到清理确认，不重复取消、刷新或创建任务；恢复不延长原截止。类型化 `failure` 展示实际根因，身份不可用不等于本站登录失效。已就绪结果过期后可显式刷新；失败、超时或取消后可重新创建任务，取消后的原意图不能刷新。`context_changed` 要求重新解析并确认规格。服务端执行规则与平台验证维护在 [解析引擎设计](../../../framefetch-server/workspace/content/design/14-解析引擎.md)，本文只规定 App 消费契约。
- 解析截止限制服务端执行，不代替服务端终态。截止后与临时 GET 故障采用 5 秒只读收敛，继续读取原意图直到终态；明确的资源或身份拒绝停止查询。前台恢复同样 GET 原意图，不能重新接单或自动刷新 generation。
- 输入变化立即清除旧解析、候选、选中格式与错误；解析、候选选择、创建互斥；格式清单不在客户端改写，放入最高 360px 的独立滚动区，默认选中服务端第一项；非 `downloadable` 直接显示服务端 `user_action`／`restriction_reason`。
- 解析结果在宽度至少 900px 且非大字体时展示媒体／规格双栏，手机为单栏。展示封面、来源、时长、选中分辨率或图集／合集数量，以及选中规格的容器、兼容策略、视频与音频编码；`export_required` 提供导入自有视频入口。
- `/downloads/new` 可通过 `intentId`、`inspectionId`、`discoveryId` 恢复；`/download-intents/:intentId` 打开持久解析。恢复分别调用原意图、inspection、来源发现的 GET，不把历史读取转成新解析。失败／取消／过期记录提供显式重新解析入口；就绪意图过期仍使用原意图刷新。没有持久意图的过期结果需回首页重新解析。
- 轮询仅在非终态运行，间隔与后台恢复有界，回前台用 GET 更新；在途请求按意图代次隔离；创建下载成功后使历史失效并 `push` 到 `/downloads/{jobId}`。
- 保留的同步 inspection 路径仅用于文章／明确权限，过期时清除旧规格与幂等键并要求重新解析。

## 下载历史与详情

- 历史：服务端分页，默认每页 10，可选 10／20／50，搜索、状态筛选或每页数量变化回第一页；列表 16:9 封面 + 标题／来源／格式 + 状态。列表项整行可点，向左轻扫显示删除，页面以弱化提示说明手势，并提供独立读屏删除动作（≥ 44px）。
- 下载列表不提供选择或批量操作；查看、重试、获取文件和删除均以单条任务为单位。删除末页末项后使用服务端总数回到可用页。
- 详情：标题、来源、格式、状态、阶段、进度、执行次数、文件可用性与时间、归类后的失败原因；活跃任务（`queued/running/retry_wait`）每 2 秒 REST 读取，终态停止；支持取消、重试、获取文件、观看、删除、进入分析。本地导入的失败／取消／制品缺失提示回首页重选文件；远程下载保留重试。幂等键由应用操作持有，不确定响应复用 key，确认成功或会话变化换 key，并发点击共享 Future。
- 私有封面通过生成客户端 + Bearer 读取为内存字节，路径限于服务端返回的 thumbnail 路径，不把 Token 写入图片 URL，按资源路径内存缓存。
- 短时下载／播放地址按操作即时签发（`POST /api/downloads/{job_id}/download-url`），不持久化、不记录日志。“观看”仅视频素材可用，应用内播放；图集／合集文件交给获取文件处理。“获取文件”交给系统浏览器处理 `Content-Disposition: attachment`。详情标题最多三行，完整标题保留在语义树。
- 平台状态：`GET /api/providers`，登录后立即预取并按会话缓存（后端约 2 秒），切 Tab 不销毁数据，下拉刷新保留现有内容；提供全部／可用／需要关注筛选与平台证据详情；冷启动用骨架占位。

## 统一处理历史

- `/history/activity` 读取 `GET /api/download-intents/history/records`，同时展示链接解析、剧本文档解析、视频分析与剧本分析，采用服务端 `record_type` 联合判别。支持类别、状态、剧本分析／改写结果类型、Skill、关键词、创建起止日期；素材详情通过 `document_id`／`download_id` 进入同素材记录。日期按本地自然日转换为 UTC，结束日期使用下一日零点上界。
- 使用服务端三元游标 `created_at + record_type + id` 前后翻页，默认 10，可选 10／20／50，不伪造总数。筛选与每页数量变化重置游标，清空筛选保留素材范围。
- 当前页存在 `status_group=processing` 记录时，每 3 秒重新读取；全部终态或查询失败后停止，进入后台取消定时器且在途读取返回后不续轮询，回前台重新读取一次。筛选变化与页面卸载取消旧查询轮询，卸载移除生命周期监听。重新读取保留原查询和游标，不创建解析。
- 处理记录仅提供单条查看和后续操作；进入解析详情后由用户明确选择规格并创建下载，不提供批量解析或批量下载入口。
- 链接解析按是否已移交打开下载或原意图，剧本文档解析打开文档，分析打开 `/analyses/:analysisId` 的精确历史记录。来源不可用仍保留已完成分析的查看入口。
