# 认证与会话

- 状态机 `restoring → signedOut → submitting → signedIn`。Access Token 只在内存；Refresh Credential 只进入 Keychain／Keystore（Android 独立 namespace，iOS 本机不迁移）；启动用 Refresh Rotation 恢复；不解析 JWT，不用 Cookie、WebView、localStorage。
- 并发 401 只触发一次刷新（单飞），其余等待同一结果；刷新失败清空会话回登录。请求在返回、401 刷新和重放边界检查**会话代次**，登出、清空与新登录改变代次，旧账号的响应或重放不进入新会话，旧刷新成功结果不写入安全存储并尽力撤销。
- 退出：立即使旧会话请求失效并清内存 Access，串行清空本地 Credential，最后尽力撤销服务端会话，撤销失败不恢复登录。Credential 写入与清理按调用顺序串行。
- 注册需邮箱验证码：`sendNativeRegistrationCode` → `registerNativeUser`；60 秒重发冷却，邮箱修改清空验证码，验证码不持久化。校验：用户名 2–32、密码 8–128（按 Unicode 字符）、邮箱标准格式、确认密码一致。
- 路由门禁：启动先显示品牌恢复页；未登录落在公开首页 `/`，`/downloads/*`、`/admin/*` 等资源路由要求会话，匿名深链接进入登录；登录后 `/` 为下载工作区；已登录访问认证页重定向 `/`；受保护深链接在恢复后继续，仅保留经校验的站内目标。
- 授权边界：普通用户与管理员共用同一 Bearer 会话；服务端负责资源所有权与角色授权，App 路由门禁只是第一层体验约束（管理入口仅 `role == admin` 显示，普通用户访问 fail closed）。
